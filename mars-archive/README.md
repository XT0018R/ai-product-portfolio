# 火星档案馆 · mars-archive

> 用 AI 把 87 场演唱会数据结构化上线，并让乐迷在"回忆墙"留下自己的现场记忆，解决"演唱会记忆无处安放"的问题。

🔗 在线 Demo：https://c6490011b9854bdcbd240c1c84892717.gz2.agentos-app.net

## 这个产品解决什么问题

华晨宇十年演唱会的「舞台形态 / 场次 / 歌单」散落各处、且常被误传；粉丝想回顾某场找不到准确信息，想分享现场记忆也没有统一阵地。这个产品做一个「权威 + 可共创」的火星演唱会档案馆——既能查每场准确信息，又能由歌迷共同书写记忆（现场照片 + 火星小故事），形成 UGC 闭环。

## 核心功能
- 演唱会数据检索：87 场正式演唱会结构化（年份 / 城市 / 场馆 / 舞台形态 / 歌单 / 新歌首唱 / 现场视频），手机端可访问
- UGC 回忆墙：上传照片、写「火星小故事」，本地保存 + 可选同步全局共享

## 为什么这样做（产品决策）

数据产品思维是核心差异点：只收正式演唱会，剔除混入的特别活动，保证档案「权威感」而非大杂烩。明确定位为「官方信息整合 + 个人回忆存放」，UGC 只是附加价值，不做成内容社区。同时为回忆墙加纯文字「火星小故事」条目，让记忆有温度、也降低 UGC 门槛。

## 技术架构
- 前端：响应式页面，支持手机访问
- 数据层：87 场演唱会结构化数据 + UGC 内容存储
- 工程方式：Vibe Coding 迭代开发，前端降级探测保证可用性

## 如何运行

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（复制 .env.example 为 .env 并填写）
cp .env.example .env

# 3. 启动开发服务
npm run dev
```

## 环境变量

```env
# 服务端口
PORT=3000

# 数据库连接（示例，请勿提交真实凭据）
DATABASE_URL=postgres://user:password@localhost:5432/mars_archive

# 数据来源 API（示例）
DATA_SOURCE_API=https://example.com/api
```
