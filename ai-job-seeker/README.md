# AI 求职系统 · ai-job-seeker

> 用六步闭环帮求职者完成人岗匹配与简历优化，把简历关键词覆盖率从 35% 提升到 85%——解决"简历投出去没回音"的问题。

## 这个产品解决什么问题

应届生求职面临三重困境：**找不到**合适的岗位（海投无回音）、**改不好**简历（关键词不匹配被 HR 初筛过滤）、**面不好**试（没有模拟环境，到了现场紧张忘词）。这个产品设计**六步全链路 AI 求职工作流**：简历解析 → 岗位匹配 → JD 逆向 → 简历优化 → 模拟面试 → 投递话术，将求职从"盲目海投"变成"精准打击"。

## 核心功能

- 人岗匹配：解析岗位 JD，与简历逐项比对并给出匹配度
- 简历优化：关键词覆盖率比对，标记已覆盖 / 部分覆盖 / 缺失，生成定向改写建议
- 模拟面试：根据目标公司信息 + JD，AI 生成面试题库并模拟面试对话，实时评分反馈
- 投递话术：根据公司 + 岗位，生成定制化打招呼话术和自我介绍

## 为什么这样做（产品决策）

- **用户痛点 → 方案**：我观察到求职者"海投无回音"的根因是简历与 JD 关键词不匹配，因此选择「六步闭环」把求职拆成可执行、可量化的流程，每步输出直接作为下一步输入。
- **取舍（指标）**：在「简历评分」和「JD 关键词覆盖率」之间优先了后者——简历"好坏"是主观的，但"JD 关键词覆盖率"是客观可量化的，HR 初筛本质就是关键词匹配，聚焦这个指标最有效。
- **取舍（AI 边界）**：AI 优化的边界是"重新包装"而非"编造经历"——只调整描述角度和关键词密度，不生成虚假经历。这是产品伦理底线，也是面试时不翻车的保障。
- **数据/验证**：关键词覆盖率从 35% 提升到 85%；单次投递全流程准备时间从 2 小时压缩到 20 分钟；日均投递量提升 3 倍。

## 技术架构

- 模型 / API：DeepSeek · Kimi（负责 JD 解析、简历诊断与改写）
- 关键能力：JD 关键词提取 · 简历定向优化 · AI 模拟面试 · 投递话术生成
- 流程引擎：六步闭环的状态编排
- 前端：结果可视化（匹配度、关键词覆盖率）

## 如何运行

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（复制 .env.example 为 .env 并填写）
cp .env.example .env

# 3. 启动开发服务
npm run dev
```

## 环境变量

```env
# 服务端口
PORT=3000

# LLM API Key（请使用你自己的 Key，切勿提交真实值）
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx

# LLM API 地址
LLM_API_BASE=https://api.example.com
```
